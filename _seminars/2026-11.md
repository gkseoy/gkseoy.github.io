### 11월 12일

#### 논문발표 주희윤
[!IMPORTANT]
*[HotStorage’24] Asymmetric RAID: Rethinking RAID for SSD Heterogeneity*

N drive RAID-5에서는 READ가 N배, WRITE가 N-1배 발생한다.

또한, 가장 성능이 낮은 HDD 또는 SSD의 성능을 따라간다.

cf) Fail-slow : 성능이 급격히 저하되는 현상 / Fail-stop : 동작이 완전히 멈추는 현상
=> **Asymmetric RAID**를 제안

Stripe가 RAID에 저장할 수 있는 용량을 결정함 (용량이 남아도 stripe로 구성할 수 없으면 사용X -> 공간낭비)

- 하나의 chunk는 하나의 SSD에 저장된다.
- 동일한 stripe에 속하는 chunk들은 각각 다른 SSD에 저장된다.

cf) SST : Stripe 상태를 관리하는 테이블

> 저자가 분석한 선행연구의 단점 외에, 제가 생각하는 단점은 무엇일까요?

### 11월 19일

#### 논문발표 김채원
[!IMPORTANT]
*[ASPLOS'23] LeaFTL: A Learning-Based Flash Translation Layer for Solid-State Drives*

SSD는 Address Mapping Table을 저장하는 RAM이 필요하다.

- 선행연구
  Block-Level-FTL : Block 단위로 Table을 만들자
  DFTL : 일부만(Hot)만 Table에 넣자
  S-FTL : 압축하자

**Log Structured 방식을 사용한 mapping table 방식**
#### 연구 Seminar
OOB(Out of Bounds) : Page에 존재하는 metadata를 저장하는 위치(다른 여러가지 정보를 저장할 수도 있음)
OP(Over Provisioning) : 공간을 따로 빼두는 것 (제조사 or 사용자)
sector 단위 -> FTL -> page 단위

Write-hole : Parity가 data랑 맞지 않는 순간이 있기도 함
-> 이걸 줄이기 위해 이전 단계인 preread를 최소화하는게 필요

> CPU가 바쁘면 SSD가 일부 작업을 대신해주는 방식들이 있음

F2FS : NAND flash 기반 file system
segement 단위 -> section 단위 (-> zone 단위(HOT/COLD)
metadata(node), file data(block)
