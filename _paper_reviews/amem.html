1. Introduction

  • 기존 메모리 시스템의 한계

LLM Agent가 장기간 사용자와 상호작용하려면 과거의 대화와 경험을 저장하고, 현재 작업에 필요한 정보를 다시 가져올 수 있어야 함.

기존 메모리 시스템은 대화 저장과 검색 기능을 제공하지만, 새로운 경험이 들어왔을 때 기존 기억을 어떻게 연결하고 재구성할지에 대한 기능은 제한적임.

예를 들어 사용자가 여러 대화에서 같은 프로젝트를 이야기하더라도, 각 대화를 독립적으로 저장하면 프로젝트의 요구사항과 변경 이력을 함께 활용하기 어려울 수 있음.

⇒ 미리 정의한 분류와 관계에 의존하는 방식이 새로운 경험을 유연하게 조직하는 데 한계가 있다고 설명함.

  • A-MEM의 아이디어
  1. 경험을 속성을 갖춘 노트로 만듦.
  2. 관련된 과거 기억을 찾아 연결 관계를 생성함.
  3. 새로운 정보를 반영하여 기존 기억의 설명과 속성을 갱신함.

이렇게 기억이 추가될 때마다 메모리 네트워크를 함께 재구성하여, 이후 검색에서 관련 경험을 더 잘 활용하도록 함.

2. Background and Motivation

Zettelkasten

A-MEM은 Zettelkasten이라는 지식 관리 방식에서 아이디어를 얻음.

Zettelkasten에서는 지식을 작은 노트로 기록하고, 관련된 노트 사이에 연결을 만듦. 새로운 내용을 알게 되면 기존 노트와 연결하면서 지식의 관계를 확장함.

원리A-MEM에서의 적용
Atomic Note하나의 독립적으로 이해할 수 있는 지식 단위를 노트로 구성함
Flexible Linking내용과 의미에 따라 관련 기억을 연결함
Continuous Evolution새로운 경험을 반영하여 기존 기억의 설명과 속성을 갱신함

하나의 노트는 여러 주제와 연결될 수 있음. 예를 들어 캐시 구현에 관한 대화는 웹 개발, 메모리 관리, 성능 최적화와 각각 관련될 수 있음.

검색과 메모리 조직의 관계

검색은 저장된 기억의 표현에 영향을 받음. 원래 대화에 현재 질문과 같은 표현이 없더라도, 해당 대화의 의미를 설명하는 키워드와 맥락이 추가되어 있으면 관련성을 찾는 데 도움이 될 수 있음.

A-MEM은 기억을 저장할 때 검색에 사용할 표현을 함께 생성하고, 이후 경험에 따라 그 표현을 갱신함.

3. A-MEM Methodology

3.1 Note Construction — 경험을 구조화된 노트로 변환

새로운 상호작용이 들어오면 원문과 시각 정보를 바탕으로 LLM이 키워드, 태그, 맥락 설명을 생성함.

키워드는 구체적인 개념을, 태그는 비교적 넓은 범주를 나타냄. Context는 해당 대화가 어떤 상황과 목적을 가진 내용인지 설명

임베딩은 원문·키워드·태그·맥락 설명을 연결한 텍스트로 생성함. 따라서 원문과 LLM이 생성한 의미 정보가 검색 표현에 함께 반영됨.

3.2 Link Generation — 관련 기억 연결

새 노트가 만들어지면 기존 기억 중 연결할 대상을 찾음.

  1. 새 노트와 기존 노트의 임베딩 사이에서 cosine similarity를 계산함.
  2. 유사도가 높은 top-k 기억을 후보로 선택함.
  3. LLM이 새 기억과 후보들의 내용·속성을 비교함.
  4. 의미 있는 관계가 있다고 판단한 기억 사이에 링크를 생성함.

임베딩 검색은 비교할 후보를 줄이는 역할을 하고, LLM은 후보 사이의 공통 개념과 맥락을 분석하여 연결 여부를 결정함.

3.3 Memory Evolution — 기존 기억 갱신

새로운 경험은 과거 경험을 이해하는 데 필요한 정보를 추가할 수 있음. A-MEM은 새 기억과 관련된 기존 노트의 context, keywords, tags를 갱신할지 판단함.

Figure 2의 캐시 개발 사례에서는 처음에 메모리와 디스크를 사용하는 캐시 구현을 요청하고, 이후 메모리 사용량 문제와 LRU 정책 도입을 이야기함.

이처럼 후속 경험이 쌓이면, 이전 기억을 새로운 요구사항과 함께 해석할 수 있도록 관련 설명과 속성을 갱신함.

갱신된 노트는 메모리 집합의 기존 노트를 대체함. 이 과정이 반복되면서 기억 사이의 공통 주제와 관계가 점차 축적됨.

3.4 Memory Retrieval — 현재 질문에 필요한 기억 검색

현재 질문에 답할 때는 질문을 임베딩으로 변환하고, 저장된 노트와의 유사도를 계산하여 top-k 기억을 선택함. 선택한 기억은 LLM의 프롬프트에 포함됨.

본문에서는 유사도 기반 top-k 검색을 정의하며, Figure 2에서는 검색된 기억과 연결된 관련 기억도 함께 활용하는 구조로 설명함.

4. Evaluation

4.1 실험 구성

주요 평가는 LoCoMo와 DialSim에서 수행함. LoCoMo는 장기간의 대화에 관한 질문을, DialSim은 장기 다자간 대화에 관한 질문을 포함함.

LoCoMo의 질문 유형은 다음과 같음.

유형평가 내용
Single Hop하나의 근거로 답할 수 있는 질문
Multi Hop여러 기억의 정보를 조합해야 하는 질문
Temporal시간과 사건 순서를 이해해야 하는 질문
Open Domain대화와 외부 지식을 함께 활용하는 질문
Adversarial대화에서 답을 찾을 수 없는 질문

주요 비교 방법은 전체 대화를 입력하는 LoCoMo baseline, ReadAgent, MemoryBank, MemGPT임.

본문에서는 GPT-4o-mini, GPT-4o, Qwen2.5 1.5B·3B, Llama 3.2 1B·3B를 사용함. 임베딩 모델은 all-MiniLM-L6-v2임.

주요 지표는 정답과 생성 답변의 단어 일치를 측정하는 F1, BLEU-1이며, 질문에 답할 때 사용한 평균 토큰 수도 보고함.

4.2 LoCoMo 성능

A-MEM은 특히 시간 관련 질문과 여러 기억을 활용하는 질문에서 개선을 보임. 다만 모델과 질문 유형에 따라 다른 방법이 더 높은 점수를 보이는 경우도 있음.

GPT-4o-mini의 대표 결과는 다음과 같음.

4.5 검색 개수 k의 영향

검색하는 기억이 많아지면 답변에 필요한 근거를 더 확보할 수 있지만, 관련성이 낮은 정보와 입력 길이도 증가함.

실험에서는 GPT-4o-mini의 k를 10, 20, 30, 40, 50으로 바꾸어 평가함.

4.6 비용과 확장성

A-MEM은 노트 임베딩을 저장하므로, 기억 수가 늘어나면 메모리 사용량도 함께 증가함.

4.7 메모리 표현 분석

노트 임베딩을 t-SNE로 2차원에 표현하여, 링크 생성과 기억 갱신을 적용했을 때 분포가 어떻게 달라지는지 관찰함.

비교 대상인 Base Memory는 LG와 ME를 제거한 A-MEM

5. Conclusion and Limitations

A-MEM은 노트 생성 → 관련 기억 연결 → 기존 기억 갱신 → 질문 기반 검색으로 장기 기억을 관리함.

새로운 경험이 들어올 때 기존 기억의 맥락과 분류를 함께 조정하여, 이후 검색과 답변에 활용할 수 있는 표현을 축적함. 실험에서는 링크 생성과 기억 갱신을 함께 사용한 구성이 높은 성능을 보였음.

논문에서 제시한 한계는 기억을 조직하는 품질이 기반 LLM의 능력에 영향을 받는다는 점임. 같은 경험에서도 모델에 따라 다른 설명과 연결이 생성될 수 있음. 현재 구현은 텍스트 중심이며, 이미지와 오디오를 포함한 기억 관리는 향후 과제로 제시함.
