1. Introduction

대규모 in-memory database와 AI·분석 애플리케이션의 메모리 사용량은 수 TB까지 커지고 있음. 이런 시스템은 빠르지만 비싼 DRAM을 near memory로, 느리지만 용량이 큰 NVM·CXL memory 등을 far memory로 사용하여 비용과 성능을 조절함.

Tiered memory가 효과적으로 동작하려면 자주 접근하는 데이터를 빠르게 찾아 near memory로 옮겨야 함. 하지만 기존 telemetry는 주소 공간 전체를 스캔하거나 일부 페이지만 sampling하므로, 메모리 footprint가 커질수록 비용이 증가하거나 hot page를 놓치기 쉬움.

Telescope는 page table의 leaf PTE뿐 아니라 PGD·PUD·PMD 같은 상위 엔트리의 ACCESSED bit도 활용함. 상위 엔트리가 접근되지 않았다면 그 아래 subtree 전체를 cold하다고 판단하여 건너뛰고, 접근 흔적이 있을 때만 하위 단계로 내려감.

이를 통해 큰 주소 공간은 넓은 단위로 확인하고, hot 영역만 점차 세분화함. 논문은 이 방식을 region-based telemetry와 MGLRU scanning에 각각 적용함.

2. Background and Motivation

2.1 Multi-level Page Table

x86-64의 4단계 page table은 PGD → PUD → PMD → PTE 순서로 virtual address를 physical page에 연결함. 4 KB page를 기준으로 각 엔트리가 담당하는 주소 범위는 다음과 같음.

단계엔트리 하나가 담당하는 범위
PGD512 GB
PUD1 GB
PMD2 MB
PTE4 KB

하드웨어가 page table walk를 수행하면 경로에 포함된 각 단계의 ACCESSED bit가 설정됨. 따라서 어떤 PTE가 가리키는 page가 접근되었다면 그 경로의 PMD·PUD·PGD에도 접근 흔적이 남음. 반대로 상위 엔트리의 bit가 설정되지 않았다면, 해당 subtree의 page들은 최근 접근되지 않았다고 볼 수 있음.

2.2 기존 Telemetry 방식의 한계

  • Linear scanning은 모든 page의 PTE를 검사하므로 정확하지만, TB 규모에서는 검사할 엔트리 수와 CPU 비용이 매우 커짐.
  • Region-based sampling은 주소 공간을 region으로 나누고 일부 page를 표본으로 확인함. 비용은 낮지만, 큰 region 안의 작은 hot 영역을 뽑지 못하면 false negative가 발생하고 수렴도 느려짐.
  • Hardware counter 방식은 PEBS 같은 PMU event를 sampling함. False positive는 줄일 수 있지만 hardware에 의존하며, TB 규모에서는 sampling되지 않은 hot page가 많아질 수 있음.

3. Telescope Design

3.1 상위 Page-table Entry 활용

Telescope는 처음부터 모든 PTE를 확인하지 않고, 넓은 범위를 담당하는 상위 단계에서 시작함. Sampling interval 시작 시 선택한 엔트리의 ACCESSED bit를 초기화하고, interval이 끝났을 때 다시 설정되었는지 확인함.

상위 엔트리에 접근 흔적이 있으면 그 subtree 안에 hot page가 있다는 뜻이므로 다음 profiling에서 더 낮은 단계로 내려감. 접근 흔적이 없으면 subtree 전체를 cold로 처리하여 수많은 leaf-level 검사를 생략함.

3.2 Region 관리와 Profiling

Region-based Telescope는 DAMON의 region 관리 방식을 활용함. 처음에는 virtual address space를 같은 크기의 region들로 나누고, profiling window 동안 각 region의 접근 횟수로 hotness score를 계산함.

  • Hot할 가능성이 있는 region은 작은 subregion으로 나누어 실제 hot page에 점차 수렴함.
  • 비슷한 cold score를 가진 인접 region은 합쳐서 관찰 비용을 줄임.
  • 각 sampling interval에는 region 크기와 경계에 맞는 page-table entry를 고르고, 해당 ACCESSED bit가 다시 설정되면 region의 접근 점수를 증가시킴.

어떤 단계의 엔트리를 선택할지는 Bounded와 Flex 두 variant에 따라 달라짐.

3.3 Bounded Variant — Region 경계를 넘지 않음

Telescope-BND는 region 경계 안에 완전히 들어오는 엔트리 중, 가능한 가장 높은 단계의 엔트리를 선택함.

예를 들어 600 GB region에서 512 GB를 담당하는 PGD 엔트리를 사용할 수 있음. 남은 범위에는 더 작은 PUD 엔트리 등을 사용함.

Region이 작아지면 큰 범위를 담당하는 상위 엔트리가 경계 안에 들어가지 못하므로, 자연스럽게 더 낮은 단계에서 관찰하게 됨.

3.4 Flex Variant — 일부 범위 초과를 허용

Telescope-FLX는 설정한 오차 한도 안에서 region 경계를 넘어서는 엔트리도 선택할 수 있음.

조금 더 넓은 범위를 관찰하더라도 상위 엔트리를 사용하면, 한 번에 더 많은 주소 공간의 접근을 감지할 수 있음. 다만 region 바깥의 접근이 해당 region의 점수에 영향을 줄 가능성이 생김.

3.5 MGLRU에 적용 — MGLRU-TS

MGLRU(Multi-Generation LRU)는 page를 여러 세대로 관리함. 최근 접근한 page는 새로운 세대로 이동하고, 오래 접근하지 않은 page는 이전 세대에 남아 memory reclaim 후보가 됨.

Telescope를 적용한 MGLRU-TS는 page table의 상위 단계부터 접근 비트를 확인함.

  • 접근 비트가 설정되어 있으면 하위 page를 확인함.
  • 설정되어 있지 않으면 해당 subtree의 스캔을 생략함.

예를 들어 PUD 엔트리 하나가 담당하는 1 GB 영역을 건너뛰면, 최대 262,144개의 4 KB page에 대한 leaf-level 검사를 생략할 수 있음.

4. Evaluation

4.1 실험 환경과 평가 기준

주요 실험은 다음과 같은 tiered memory 환경에서 수행함.

항목설정
CPUIntel Xeon Gold 6238M, 4 sockets
Near MemoryDRAM 768 GB
Far MemoryIntel Optane DC PMM 6 TB
OS / KernelFedora 30 / Linux 5.18.19
기본 page 크기4 KB

DAMON과 PMU는 moderate·aggressive 설정을, Telescope는 Bounded·Flex를 비교함.

탐지 성능은 다음 두 지표로 평가함.

  • Precision — hot하다고 판단한 page 중 실제 hot page의 비율
  • Recall — 실제 hot page 중 탐지한 page의 비율

4.2 5 TB에서 변화하는 Hot 영역 탐지

MASIM으로 5 TB의 memory를 할당하고 접근 영역을 세 단계로 바꿈.

  1. 하나의 10 GB 영역에 접근함.
  2. 다른 10 GB 영역으로 접근 위치를 옮김.
  3. 서로 다른 두 개의 10 GB 영역에 접근함.

Telescope는 큰 주소 공간에서 작은 hot 영역을 찾고, 접근 위치가 바뀐 뒤에도 다시 탐지할 수 있었음.

2 MB huge page를 사용한 실험에서는 DAMON도 높은 탐지 성능을 보임. Telescope는 같은 조건에서 평균 precision 0.96, recall 0.97을 달성함.

4.3 관찰 비용

상위 엔트리 하나로 큰 영역을 확인할 수 있으므로, Telescope는 접근 비트를 초기화하고 확인하는 작업을 줄일 수 있음.

4.4 실제 애플리케이션 — Memcached와 Redis

Memcached·Redis에 Memtier·YCSB 부하를 조합하여 네 가지 시나리오를 평가함.

데이터를 처음에는 far memory에 배치하고, 150초 warmup 이후 hot 영역을 찾아 DRAM으로 이동함. 실험의 이동 정책은 다음과 같음.

  • 120초 동안 접근 점수가 5를 초과한 region을 hot 후보로 선택함.
  • 4 GB 이상의 큰 region은 더 세분화될 때까지 이동을 미룸.
  • 점수가 높은 영역부터 선택하며 한 번에 최대 10 GB까지 이동함.

4.5 MGLRU-TS — Cold 데이터 회수

별도의 1 TB DRAM 시스템에서 Memcached 데이터를 약 976 GB 채우고, MGLRU 스캔 후 cold data 10 GB를 zswap 압축 풀로 보내는 작업을 반복함.

MGLRU-TS는 접근 흔적이 없는 subtree를 건너뛰어 스캔을 빠르게 끝내고, cold page를 더 일찍 회수할 수 있었음.

5. Conclusion

Telescope는 상위 page-table entry의 접근 흔적을 활용하여 관찰 범위를 좁히는 telemetry 기법임.

Region 기반 방식에서는 hot 영역을 점차 세분화하고, MGLRU에서는 접근 흔적이 없는 subtree의 스캔을 생략함. 이를 통해 5 TB 실험에서 높은 탐지 성능과 낮은 CPU 사용량을 보였으며, 실제 tiered memory 환경에서도 데이터 배치 개선으로 처리량을 높였음.

논문은 같은 원리를 5단계 page table에도 적용하여 더 큰 주소 공간으로 확장할 수 있다고 설명함. 실험으로 검증한 범위는 최대 5 TB microbenchmark와 1–2 TB 실제 애플리케이션임.
